# Sourccey MolmoAct2 on a 5090

Use this runbook when you want to fine-tune MolmoAct2 on a Sourccey dataset and then run the checkpoint back on the robot from a single RTX 5090 workstation.

The short version:

- Install both the `sourccey` and `molmoact2` extras.
- Start with LoRA fine-tuning, `bfloat16`, gradient checkpointing, and a modest batch size.
- Start rollout in `continuous` inference mode.
- Keep the first rollout conservative at `10-15 FPS`, then raise it if the loop stays stable.

## 0) Install the right extras

```bash
uv sync --locked --extra sourccey --extra molmoact2
```

If you have not already compiled the Sourccey protobuf files:

```bash
uv run python src/lerobot/robots/sourccey/sourccey/protobuf/compile.py
```

## 1) Inspect your dataset before training

MolmoAct2 needs the correct image keys, and Sourccey datasets can vary depending on how they were recorded.

Set your dataset once:

```bash
HF_LEROBOT_HOME="${HOME}/.cache/huggingface/lerobot"
DATASET_REPO="your-org/your-sourccey-dataset"
DATASET_ROOT="${HF_LEROBOT_HOME}/${DATASET_REPO}"
```

Print the dataset features:

```bash
uv run lerobot-edit-dataset \
  --repo_id "$DATASET_REPO" \
  --root "$DATASET_ROOT" \
  --operation.type info \
  --operation.show_features true
```

Things to confirm before you train:

- Your image feature keys. For a full Sourccey setup they are often `observation.images.front_left`, `observation.images.front_right`, `observation.images.wrist_left`, and `observation.images.wrist_right`.
- Your task string is sensible and consistent across episodes.
- Your dataset is already cleaned and usable. If not, use [sourccey-dataset.mdx](./sourccey-dataset.mdx).

## 2) Recommended 5090 training recipe

For a 5090, the safest starting point is not full fine-tuning. Start with:

- `policy.enable_lora_vlm=true`
- `policy.model_dtype=bfloat16`
- `policy.gradient_checkpointing=true`
- `batch_size=8`
- `policy.action_mode=both`

That gives you a practical balance between memory, training speed, and keeping both continuous and discrete action heads available later.

Example command:

```bash
CUDA_VISIBLE_DEVICES=0 uv run lerobot-train \
  --dataset.repo_id="$DATASET_REPO" \
  --dataset.root="$DATASET_ROOT" \
  --dataset.video_backend=pyav \
  --dataset.image_transforms.enable=true \
  --policy.type=molmoact2 \
  --policy.checkpoint_path=allenai/MolmoAct2 \
  --policy.device=cuda \
  --policy.model_dtype=bfloat16 \
  --policy.action_mode=both \
  --policy.enable_lora_vlm=true \
  --policy.gradient_checkpointing=true \
  --policy.freeze_embedding=true \
  --policy.chunk_size=10 \
  --policy.n_action_steps=10 \
  --policy.num_flow_timesteps=8 \
  --policy.normalize_gripper=false \
  --policy.setup_type="dual-arm mobile manipulation robot with two front cameras and two wrist cameras" \
  --policy.control_mode="delta joint pose with base velocity and vertical lift position" \
  --policy.image_keys='["observation.images.front_left","observation.images.front_right","observation.images.wrist_left","observation.images.wrist_right"]' \
  --batch_size=8 \
  --steps=50000 \
  --save_freq=5000 \
  --log_freq=20 \
  --num_workers=4 \
  --wandb.enable=false \
  --policy.push_to_hub=false \
  --output_dir=outputs/train/molmoact2__sourccey \
  --job_name=molmoact2__sourccey
```

Notes:

- Replace `policy.image_keys` with the exact image keys from your dataset if they differ.
- If your dataset only has two cameras, use just those two keys.
- The `setup_type` and `control_mode` strings matter because MolmoAct2 uses them in its prompt. Keep them accurate and stable across runs.
- `policy.checkpoint_path=allenai/MolmoAct2` is the cleanest starting point for a custom Sourccey task. You do not need `policy.norm_tag` for this training path.

## 3) If the 5090 runs out of memory

Use these steps in order:

1. Drop `--batch_size` from `8` to `4`, then to `2`.
2. Reduce `--num_workers` from `4` to `2`.
3. Train with only the camera views that matter most.
4. Switch to the lower-memory continuous-only recipe below.

Lower-memory fallback:

```bash
CUDA_VISIBLE_DEVICES=0 uv run lerobot-train \
  --dataset.repo_id="$DATASET_REPO" \
  --dataset.root="$DATASET_ROOT" \
  --dataset.video_backend=pyav \
  --policy.type=molmoact2 \
  --policy.checkpoint_path=allenai/MolmoAct2 \
  --policy.device=cuda \
  --policy.model_dtype=bfloat16 \
  --policy.action_mode=continuous \
  --policy.train_action_expert_only=true \
  --policy.gradient_checkpointing=true \
  --policy.chunk_size=10 \
  --policy.n_action_steps=10 \
  --policy.num_flow_timesteps=8 \
  --policy.setup_type="dual-arm mobile manipulation robot with two front cameras and two wrist cameras" \
  --policy.control_mode="delta joint pose with base velocity and vertical lift position" \
  --policy.image_keys='["observation.images.front_left","observation.images.front_right","observation.images.wrist_left","observation.images.wrist_right"]' \
  --batch_size=16 \
  --steps=50000 \
  --save_freq=5000 \
  --log_freq=20 \
  --num_workers=2 \
  --wandb.enable=false \
  --policy.push_to_hub=false \
  --output_dir=outputs/train/molmoact2_continuous__sourccey \
  --job_name=molmoact2_continuous__sourccey
```

This fallback is a good option when you mainly care about continuous rollout quality on the real robot and want the most forgiving memory profile.

## 4) Which checkpoint to use for rollout

After training, use the saved `pretrained_model` directory from the checkpoint you want, for example:

```text
outputs/train/molmoact2__sourccey/checkpoints/50000/pretrained_model
```

If you are not sure which checkpoint to try first, start with the latest saved checkpoint and then compare it against one or two earlier checkpoints if rollout quality looks unstable.

## 5) Start the robot host

On the Sourccey robot host:

```bash
uv run -m lerobot.robots.sourccey.sourccey.sourccey.sourccey_host
```

## 6) Run MolmoAct2 on Sourccey

Start with synchronous inference and continuous action mode:

```bash
CUDA_VISIBLE_DEVICES=0 uv run lerobot-rollout \
  --strategy.type=base \
  --policy.path="outputs/train/molmoact2__sourccey/checkpoints/50000/pretrained_model" \
  --policy.device=cuda \
  --policy.model_dtype=bfloat16 \
  --policy.use_amp=true \
  --policy.inference_action_mode=continuous \
  --policy.enable_inference_cuda_graph=true \
  --robot.type=sourccey_client \
  --robot.remote_ip=192.168.1.212 \
  --task="Fold the shirt" \
  --display_data=false \
  --duration=600 \
  --fps=10
```

If that is stable, try `--fps=15`, then `--fps=20`.

## 7) If rollout is too slow

Try these changes in order:

- Keep `--display_data=false`.
- Lower `--fps` back to `10`.
- Use fewer image keys during training and retrain.
- Keep `--policy.inference_action_mode=continuous`.

If you want to try RTC inference for extra headroom:

```bash
CUDA_VISIBLE_DEVICES=0 uv run lerobot-rollout \
  --strategy.type=base \
  --inference.type=rtc \
  --inference.rtc.execution_horizon=5 \
  --policy.path="outputs/train/molmoact2__sourccey/checkpoints/50000/pretrained_model" \
  --policy.device=cuda \
  --policy.model_dtype=bfloat16 \
  --policy.use_amp=true \
  --policy.inference_action_mode=continuous \
  --robot.type=sourccey_client \
  --robot.remote_ip=192.168.1.212 \
  --task="Fold the shirt" \
  --display_data=false \
  --duration=600 \
  --fps=15
```

## 8) Practical defaults I would use first

If you want the shortest path to a first real run on a 5090, I would start here:

- 4 cameras if the dataset quality is good, otherwise 2 cameras
- `policy.enable_lora_vlm=true`
- `policy.action_mode=both`
- `policy.chunk_size=10`
- `policy.n_action_steps=10`
- `batch_size=8`
- `steps=50000`
- rollout with `continuous` inference at `10 FPS`

Then adjust only one thing at a time:

- raise FPS
- raise batch size
- move from 2 cameras to 4 cameras
- switch from LoRA to heavier fine-tuning only if you actually need it
