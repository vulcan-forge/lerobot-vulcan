# Sourccey SFT training

> Status: Internal runbook

Run from the repository root. Set `CUDA_VISIBLE_DEVICES` to the GPU you want to use.

## Start training

```bash
CUDA_VISIBLE_DEVICES=1 \
uv run lerobot-sft \
  --config_path=src/lerobot/scripts/sourccey/train/configs/sft_recipes/shirt_fold_c_010.yaml
```

The recipe's `output_dir` must not already exist when starting a new run.

## Two-GPU training

Launch one distributed worker per GPU with Accelerate. The pile-fold recipe
stores its per-GPU batch size of 8 and its 250,000-step sample budget, producing
a global batch size of 16 across two workers.

```bash
CUDA_VISIBLE_DEVICES=0,1 \
uv run accelerate launch \
  --multi_gpu \
  --num_processes=2 \
  --mixed_precision=bf16 \
  -m lerobot.scripts.sourccey.train.sft \
  --config_path=src/lerobot/scripts/sourccey/train/configs/sft_recipes/pile_shirt_fold_010_000.yaml
```

The startup log should report `Effective batch size: 8 x 2 = 16`.

`--main_process_port` is optional for a single distributed job. Accelerate
uses its default rendezvous port when it is omitted. If that port is occupied,
or if multiple distributed jobs are running on the same machine, give each job
a different port, for example:

```bash
--main_process_port=29501
```

Do not wrap this command with `lerobot-sft-retry`: the current retry wrapper
launches a single training process and is not distributed-launch aware.

## Resume training with automatic retry

```bash
CUDA_VISIBLE_DEVICES=1 \
uv run lerobot-sft-retry \
  --max-attempts=30 \
  --retry-delay-seconds=20 \
  --resume=true \
  --config_path=outputs/sft/xvla_s_sourccey-shirt-fold-c-010-pre-000/checkpoints/150000/pretrained_model/train_config.json
```

Always resume with the checkpoint's `train_config.json`, not the original recipe.
If no emergency checkpoint was saved, this resumes from the latest periodic checkpoint.
After a failed attempt, the retry wrapper resumes from
`<output_dir>/checkpoints/last/pretrained_model/train_config.json`.
