# Train SIVA on Sourccey shirt-fold C-010

Run these commands from the repository root. The conversion starts SIVA from
the C-009 XVLA checkpoint, and the YAML recipe trains it on the local C-010
dataset.

## 1. Convert XVLA C-009 to SIVA

```bash
uv run lerobot-convert-xvla-to-siva \
  --source=outputs/train/xvla_s_sourccey-shirt-fold-c-009/checkpoints/1000000/pretrained_model \
  --output-dir=outputs/converted/xvla_s_sourccey-shirt-fold-c-009-to-siva
```

The output directory must not already contain files. If a previous conversion
is there, either use it or move it aside before rerunning the command.

Conversion transfers the compatible Florence VLM weights and the XVLA
preprocessor/postprocessor files. SIVA's context slots, router, motion priors,
and flow action decoder are new modules that will be learned on C-010. The VLM
is frozen by default; add `--train-vlm` only if you intentionally want to
fine-tune it.

## 2. Train SIVA 1 with Florence caching

The recipe is
[`siva_shirt_fold_c_010_cached.yaml`](../../../../scripts/sourccey/train/configs/siva_recipes/siva_shirt_fold_c_010_cached.yaml).
It uses the converted checkpoint above and the local dataset at
`/home/sourccey/.cache/huggingface/lerobot/Combination/sourccey-shirt-fold-c-010`.

```bash
CUDA_VISIBLE_DEVICES=1 uv run lerobot-train-retry \
  --max-attempts=30 \
  --retry-delay-seconds=20 \
  --config_path=src/lerobot/scripts/sourccey/train/configs/siva_recipes/siva_shirt_fold_c_010_cached.yaml
```

The recipe trains for 1,000,000 steps with a batch size of 8, saves every
100,000 steps, and writes the model to
`outputs/train/siva_sourccey-shirt-fold-c-010-cached`.

The cache is filled lazily: the first visit to a dataset sample runs the frozen
Florence model and stores its output in
`outputs/cache/siva_shirt_fold_c_010/florence_features.sqlite`; later visits to
that sample read the cached tensors. Keep `freeze_vlm=true` and image transforms
disabled so a dataset index always maps to the same Florence output.

SIVA 1 and SIVA2 use different cache formats. Do not point this command at a
SIVA2 cache database. Florence feature caches can also grow very large, so
monitor the cache and available disk space while training:

```bash
watch -n 30 'du -sh outputs/cache/siva_shirt_fold_c_010; df -h .'
```

Change `CUDA_VISIBLE_DEVICES=1` if the intended GPU has a different index. The
retry wrapper automatically resumes from the last safe checkpoint after a
failed attempt.

Resume this cached SIVA 1 run explicitly with:

```bash
CUDA_VISIBLE_DEVICES=1 uv run lerobot-train-retry \
  --max-attempts=30 \
  --retry-delay-seconds=20 \
  --output_dir=outputs/train/siva_sourccey-shirt-fold-c-010-cached \
  --save_freq=100000 \
  --resume=true \
  --config_path=outputs/train/siva_sourccey-shirt-fold-c-010-cached/checkpoints/last/pretrained_model/train_config.json
```

## Resume SIVA and SIVA2

Resume from the checkpoint's `train_config.json`, not from the original YAML
recipe. These commands retain automatic retry behavior and save a checkpoint
every 100,000 steps.

Resume SIVA on GPU 1:

```bash
CUDA_VISIBLE_DEVICES=1 uv run lerobot-train-retry \
  --max-attempts=30 \
  --retry-delay-seconds=20 \
  --output_dir=outputs/train/siva_sourccey-shirt-fold-c-010 \
  --save_freq=100000 \
  --resume=true \
  --config_path=outputs/train/siva_sourccey-shirt-fold-c-010/checkpoints/0250000/pretrained_model/train_config.json
```

Resume SIVA2 on GPU 0:

```bash
CUDA_VISIBLE_DEVICES=0 uv run lerobot-train-retry \
  --max-attempts=30 \
  --retry-delay-seconds=20 \
  --output_dir=outputs/train/siva2_sourccey-shirt-fold-c-010 \
  --save_freq=100000 \
  --resume=true \
  --config_path=outputs/train/siva2_sourccey-shirt-fold-c-010/checkpoints/last/pretrained_model/train_config.json
```

Run the commands in separate terminals to train both models concurrently. If
you run only one model, set `CUDA_VISIBLE_DEVICES` to whichever GPU you want it
to use. Do not launch both models on the same GPU unless it has enough memory
for both training jobs.
